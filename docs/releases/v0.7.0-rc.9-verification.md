# Rocker v0.7.0-rc.9 Verification

Date: 2026-09-24
Source: `dev/v0.7-sftp`; release tag `v0.7.0-rc.9`

## Scope

- Dotfiles are hidden by default in each pane. The Local and remote controls
  are independent, and visibility is not persisted between SFTP sessions.
- Name sorts ascending by default. Name, Date Modified, Size, and Kind support
  ascending and descending sorting.
- Forest SFTP uses a light-gray canvas, pane, and header palette. The route
  breadcrumb and native window chrome follow that palette only while the SFTP
  destination is active. Other destinations retain the existing colors.
- No storage schema or transfer lifecycle migration is introduced.

## v0.7 Roadmap Snapshot

Four of the six SFTP feature groups are implemented; two remain partial.

| Feature group | Status | Evidence / remaining work |
| --- | --- | --- |
| Remote directory listing and path navigation | Complete | Real SFTP manager and fixture-backed workspace tests. |
| Upload/download, drag-and-drop, task ownership | Complete | Main-process transfer tasks and integration/UI tests. |
| Refresh, folder creation, rename, and delete | Complete | Fixture-backed operations and UI confirmation tests. |
| File metadata | Partial | Size and modified time are visible. The main two-pane table intentionally has the approved four columns and does not display permissions or owner IDs, although the bridge supplies them. |
| Transfer progress, cancellation, retry, and errors | Partial | The manager exposes task lifecycle APIs; the main two-pane page shows one status/progress row with cancel/dismiss, but does not expose retry or detailed failure text. |
| Separate SFTP lease sharing the verified SSH transport | Complete | Integration tests verify transport sharing and independent workspace/transfer ownership. |

The automated suite exercises real fixture-backed directory operations,
upload/download, path traversal rejection, moves, and transfers surviving page
close. Dedicated cancellation-release and concurrent-transfer acceptance tests
remain advisable. Native packaged Windows/macOS installation and real-host
permission, disconnect, cancellation, retry, and slow-transfer smoke checks are
still required before final v0.7.0. Transfer persistence/resume remains
intentionally out of scope unless product requirements change.
