## Release Asset Policy

The local Windows output also contains blockmaps, an archless intermediate
installer, and the unpacked payload. These are build intermediates. The CI
release job copies only the six allow-listed assets into a clean directory:

```text
Rocker-v0.3.3-x64.exe
Rocker-v0.3.3-arm64.exe
Rocker-v0.3.3-x64.dmg
Rocker-v0.3.3-arm64.dmg
Rocker-v0.3.3-x64.zip
Rocker-v0.3.3-arm64.zip
```

The release allow-list rejects blockmaps, debug metadata, unpacked
directories, archless installers, and duplicate paths before upload.

## Storage and Bootstrap Closure

- The Electron main process owns all app-data files and serializes updates per
  store path.
- Atomic writes use same-directory temporary files and retain a valid `.bak`
  before replacement.
- Settings, History, and Workspace may recover or default according to policy.
- Hosts, Credentials, and Host Keys fail closed when neither primary nor backup
  data is valid.
- A blocked Workspace keeps renderer persistence disabled; failed bootstrap
  cannot overwrite the existing workspace with an empty default.
- Bootstrap payloads contain no credential values, Host Key values, absolute
  identity paths, or raw filesystem errors.
