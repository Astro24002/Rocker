# v0.5-A Host Workflow Verification

Date: 2026-09-10
Status: Implemented in the working tree; not a release record
Scope: Host workflow closeout before Trust management

## Implemented

- HostStore duplicate and favorite mutations run through the serialized main-process queue.
- Duplicate creates a fresh profile without password, passphrase, identity-file, private-key, snippet, or favorite state.
- Existing Host deletion remains responsible for protected credential cleanup and does not close an existing Terminal Session.
- Host groups use exact normalized identity and Recent Hosts are derived from successful History outcomes, capped at eight unique Host IDs.
- Typed bridge, preload, browser preview, and validated IPC handlers expose duplicate and favorite operations.
- The compact card workspace keeps single-click selection, double-click connect, and hover-only Edit. The selected card reveals Edit, Duplicate, Favorite/Unfavorite, and Delete actions.
- App owns canonical Host mutations and passes the HostEditor save Promise through unchanged so rejected persistence remains visible in the drawer.
- Trust inventory, tags, environment policy, connection test, Host charset/theme consumption, and Snippet execution remain deferred.
