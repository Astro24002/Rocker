# Rocker Workspace Implementation Verification

Date: 2026-09-17
Baseline HEAD: `6d7162a0d19a14250e946961aed28455f2e0ebe2`

## Implemented

- The shell exposes Hosts, SFTP, Snippets, Port Forwarding, Connections, and Settings in English by default, with the existing Chinese locale still selectable.
- Sessions remain a single untitled list. There is no restored top tab strip, environment, tag, or group navigation.
- Host cards support search, favorites-only filtering, direct connect, and name, recent, and favorite-first ordering.
- Connections contains the existing History and Trust features as internal tabs.
- SSH connects continue to use the Electron main-process connection manager, PTY rental lifecycle, preload `RockerBridge`, and xterm surface. Reusing an existing host SSH session selects it; the existing copy command still creates an independent SSH session.
- PF pages are opened on demand and reuse one page per host/window. They reflect the existing main-process forwarding manager state, but forwarding ownership remains independent of page visibility and page close.
- SFTP pages are opened on demand and reuse one page per host/window. Their path and pending/error metadata are persisted as workspace state.
- Theme preferences include a global theme and optional per-host override. Semantic theme tokens scope to the workspace/terminal session surfaces, so changing theme does not remount xterm or clear terminal output.

## Storage Compatibility

- Settings storage normalizes missing theme, host sort, favorite filter, and Connections-tab values to defaults.
- Workspace sessions with no `kind` normalize as SSH. SFTP path and PF profile/protocol metadata are optional and backward compatible.
- Existing host organization fields remain readable in persisted records. New direct-host, duplicate-host, and editor writes omit `group`, `environment`, and `tags`.

## Deliberate Limits / Follow-up

- There is no Electron SFTP service or preload API in this codebase. The SFTP page is therefore an honest workspace route and persisted browser-state shell, not a fake file browser or transfer implementation. Real directory listing, transfer, and error mapping require a main-process SFTP implementation and bridge contract.
- Browser Preview is not implemented. PF protocol is optional metadata and never inferred from a port number; an embedded preview must wait for an explicit, trusted protocol-confirmation design.
- The legacy host-organization cleanup has no versioned backup-and-rollback migration yet. Old records are retained and read compatibly; a recoverable migration is still required before permanently removing those fields from stored documents.
- Native Windows/macOS interaction checks remain manual work. On this Linux environment, `npm run dev` built the main/preload and renderer, then Electron aborted because its `chrome-sandbox` helper lacks the required root ownership and `4755` mode. The sandbox was not disabled to bypass that host configuration. No package was produced and no branch was pushed.
