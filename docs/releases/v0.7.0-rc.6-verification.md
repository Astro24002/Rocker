# Rocker v0.7.0-rc.6 Verification

Date: 2026-09-23
Source: `dev/v0.7-sftp`; release tag `v0.7.0-rc.6`

## Scope

- Remote-to-remote SFTP file and folder moves use the owner-scoped bridge and
  real main-process SFTP rename operation, represented by the existing task
  lifecycle.
- Moving source entries cannot be selected or dragged while queued/running;
  they unlock when the task reaches a terminal state.
- The SFTP workspace renders one move status/progress row inside the white
  workspace area only while a move is queued/running. Upload/download and
  terminal move tasks do not render that row.
- Windows work-area maximization saves and restores the window resizable state.
- No storage schema migration is introduced.

## Candidate Limitations

Real-host SFTP moves and Windows taskbar behavior still require manual
packaged-app validation. Remote rename has no byte-level progress callback, so
the move indicator is indeterminate. Tasks do not resume across application
restarts.
