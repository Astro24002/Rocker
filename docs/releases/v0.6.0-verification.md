## Product Boundary

Implemented:

- Global Port Forwarding is a separate overview destination. It has no create
  action, works without an open Host Session, and lists saved forwarding
  profiles as `Forwarding`, `Suspended`, or `Stopped`.
- Host-local forwarding is a separate Host workspace destination. It is reached
  from the Session context menu's single new `Port forwarding` action and owns
  profile create, edit, start, stop, resume, remove, copy, open, and discovery
  actions.
- A forwarding profile is bound to a saved Host. Loading profiles never starts
  a listener; a stopped profile starts only after an explicit user action.
- Terminal Sessions and forwarding runtimes use independent leases and
  channels while reusing an eligible owner-scoped SSH transport.
- Host deletion stops forwarding runtimes before removing profiles and Host
  credentials. Closing a terminal releases only its terminal lease.
- Template and encrypted configuration exports include sanitized forwarding
  profiles. Imports preview profile conflicts, require an explicit conflict
  choice, journal replacement, and never start listeners.

## Browser Preview Evidence

The renderer was served with:

```text
npx vite --host 127.0.0.1 --port 5175
```

HTTP smoke check: `GET /` returned `200 OK`; the renderer entry transformed
without Vite errors.

Manual interaction path:

1. Open `http://127.0.0.1:5175/` with no Session selected and choose
   `Port Forwarding` in the Sidebar. The overview shows saved demo profiles and
   does not render `New forwarding`.
2. Use `Start forwarding` on a stopped row. The browser preview creates an
   in-memory runtime and changes the row to `Forwarding`; `Stop forwarding`
   returns it to `Stopped` without removing the profile.
3. Open a demo Host, then open the Session context menu. `Port forwarding` is
   the only forwarding entry and routes to the Host-local page.
4. Choose `New forwarding`, fill the route, and use either `Save profile` or
   `Save and start`. Selecting local address `0.0.0.0` shows the exposure
   warning. The discovered-service path remains explicit and does not auto
   start a rule.

The browser preview bridge is intentionally in-memory and does not establish a
real SSH connection. Native SSH, Host Key prompts, and local listeners require
the Electron runtime.
