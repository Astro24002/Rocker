# Rocker v0.8.1-rc.4

This prerelease adds the first Workspace / Codex Workbench integration.

- Create Local, Remote, or Cloud project cards. Remote and Cloud use a saved
  SSH Host; Cloud means your supplied SSH environment.
- Open a graphical Codex conversation by default, create independent
  sessions, send and stop tasks, and respond to approval or input requests.
- Open a terminal only when needed. Switching pages preserves the running
  conversation and terminal; closing an active task requires confirmation.
- Resume a disconnected conversation explicitly without automatically
  replaying its last task. Existing SSH/SFTP/PF sessions keep their own
  connection and task lifecycles.

Codex must be installed and signed in on the execution machine. Rocker does
not bundle Codex or copy login credentials between machines. This integration
was tested with Codex CLI 0.165.0. Use an absolute executable path if Codex is
not available on the desktop or noninteractive SSH PATH. Remote targets
currently require a POSIX shell.

Workspace profiles are stored in the new `workbenches.json`; existing stored
data needs no migration. Open Codex sessions are not restored across app
restarts. Profile export/import, historical-thread browsing and Codex session
duplication into another window are not included in this increment.

Validation includes automated lifecycle/UI tests, production builds, and
actual Codex handshake and PTY operations locally and through a loopback SSH
test server. Browser conversation fixtures are UI tests only. Real model
tasks, external-host acceptance and native installation/use acceptance remain
pending. The previously reported first-launch terminal issue is not claimed
fixed. This is a prerelease, not a stable release.
