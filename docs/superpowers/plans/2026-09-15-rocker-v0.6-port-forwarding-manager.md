# Rocker v0.6 Port Forwarding Manager Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Host-bound forwarding profiles with two separate renderer destinations: a global restartable overview and a Host-local create/manage view backed by shared SSH transports.

**Architecture:** Persist profiles in a dedicated `ForwardingProfileStore`; keep `ForwardingManager` responsible for transient listeners and leases; extend `SshConnectionManager` with owner-scoped Host-based forwarding acquisition so a profile can start without a terminal. Expose profile/runtime operations through validated IPC, join profiles with runtime state for the renderer, and keep terminal and forwarding lifecycles independent.

**Tech Stack:** TypeScript, Electron IPC/contextBridge, React 19, Vitest, Testing Library, existing `JsonStore`, `ssh2`, existing i18n and tokenized CSS.

**Spec:** `docs/superpowers/specs/2026-09-15-rocker-v0.6-port-forwarding-manager-design.md`

## Global Constraints

- Global Port Forwarding and Host-local forwarding are separate destinations.
- The global page works with zero Host Sessions and has no create action.
- Suspended and stopped profiles are visible globally and can be started or resumed.
- A Session context menu adds only `Port forwarding` and routes to the current Host-local page.
- New profiles are created only in a Host context and are bound to a saved Host.
- Multiple terminal Sessions and forwarding runtimes for one Host share an eligible SSH transport while keeping independent channels and lifecycles.
- Profile import/export is sanitized, versioned, conflict-aware, and never starts listeners implicitly.
- Every visible string and user-facing error is localized in English and Simplified Chinese.
- Release verification is `npm run typecheck`, `npm test`, `npm run build`, and `git diff --check`.
