# Rocker v0.3.1 Engineering Plan Index
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the approved v0.3.1 reliability design into three independently reviewable implementation plans while keeping implementation paused until the product owner explicitly starts it.

**Architecture:** Preserve the current main/renderer split. `SshConnectionManager` owns transport and shared connection leases, `TerminalSessionManager` owns PTY sessions, the renderer consumes typed events, and diagnostics remain local to the Electron main process.

**Tech Stack:** Electron, TypeScript, React, xterm.js, ssh2, Vitest, GitHub Actions.

**Spec:** [v0.3.1 reliability design](../specs/2026-08-28-rocker-v0.3.1-reliability-design.md)

## Global Constraints

- Do not reintroduce the removed legacy SSH API or React-managed terminal output buffers.
- Do not log credentials, private key material, complete SSH configuration, terminal input/output, remote file contents, or raw host-key fingerprints.
- Automatic reconnect is limited to `network`, `timeout`, and `dns`; authentication, host-key, configuration, and cancellation failures stop retrying.
- Preserve the current workspace/session reuse contract: same host, credential identity, and verified host key may share one underlying connection.
- Every implementation task starts with a failing focused test and ends with the focused test, typecheck, and relevant full-suite verification.
- This document is a plan only. No implementation work begins until an explicit start command.

## Plan Order

1. [ ] Execute the real SSH fixture and integration contract first. It provides a reliable transport-level regression harness for the state machine.
2. [ ] Execute terminal reliability and failure UX. It consumes the integration contract and stabilizes state/event semantics.
3. [ ] Execute diagnostics and export. It observes the stabilized event/error vocabulary without changing transport ownership.
4. [ ] Execute the CI quality gate updates and run the full release verification matrix.
