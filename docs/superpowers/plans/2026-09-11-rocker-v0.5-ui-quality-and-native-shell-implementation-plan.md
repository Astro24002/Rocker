# Rocker v0.5.x UI Quality and Native Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the audited Rocker UI quality gaps in five independently verifiable `v0.5.x` increments without expanding the approved desktop product surface.

**Architecture:** Keep the existing React renderer and typed Electron bridge. Accessibility and localization remain renderer concerns; platform window presentation reads the existing `bridge.app.platform`; workspace resilience preserves the existing Session/controller ownership rather than adding new runtime metadata. CSS remains token-driven, and xterm.js remains the terminal buffer owner.

**Tech Stack:** Electron, React 19, TypeScript, xterm.js, Lucide React, Vitest, Testing Library, CSS semantic tokens, existing typed preload bridge.

**Spec:** `docs/superpowers/specs/2026-09-11-rocker-v0.5-ui-quality-and-native-shell-design.md`

## Global Constraints

- Preserve the continuous two-column Windows/macOS desktop shell and terminal-first right Workspace.
- Preserve same-window SSH connection reuse, Host Key verification, credential protection, restore, forwarding ownership, and diagnostic sanitization.
- Keep the Rocker Dark `#0AA344` semantic accent and Lucide icon family.
- Do not add SFTP, Snippets execution, Local Terminal, monitoring, Mobile, AI, cloud sync, ProxyJump, SOCKS5, remote forwarding, or a new global shortcut family.
- Do not make native launch or long soak a v0 release gate; record their status separately.
- Do not edit unrelated dirty-worktree files or reset user changes.
- Each task must have focused tests before implementation and must leave `npm run typecheck` passing.
