# Local Diagnostics and Export Implementation Plan
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give users a local, user-triggered diagnostics export that explains connection failures without collecting secrets or uploading data.

**Architecture:** A main-process `DiagnosticLogger` receives sanitized structured events from connection/session/forwarding boundaries, stores a bounded local JSONL history under Electron `userData`, and exports one JSON document through a native save dialog. Renderer code can request export through the typed preload bridge but never reads the log file directly.

**Tech Stack:** Electron, Node `fs/promises`, TypeScript, Vitest, React, Testing Library.

**Spec:** Diagnostics are local by default, opt-in export, no upload. Never record passwords, private keys/passphrases, complete SSH configuration, terminal input/output, remote file contents, or raw host-key fingerprints.

## Global Constraints

- Diagnostics must fail open for the product: a logging or export error must not tear down an SSH session.
- Use a bounded ring (for example 500 events) and bounded event/message sizes.
- Record categories and safe metadata, not arbitrary error objects or command strings.
- Export schema must be versioned and deterministic enough for support triage.
- No network client, telemetry endpoint, or background upload is introduced.

- [ ] Add failing tests for bounded strings, event count, and stable category values. Unknown values must become `unknown`, never be serialized verbatim.
- [ ] Define:
  ```ts
  type DiagnosticEvent = {
    at: string; category: "connection" | "session" | "forwarding" | "window" | "system";
    action: string; state?: string; reason?: TerminalFailureReason;
    hostId?: string; connectionId?: string; sessionId?: string;
    attempt?: number; durationMs?: number; details?: Record<string, string | number | boolean>;
  }
  type DiagnosticExport = { schemaVersion: 1; generatedAt: string; appVersion: string;
    platform: string; arch: string; events: DiagnosticEvent[]; settings: SafeSettingsSnapshot;
    lastError?: { category: string; reason?: string; message: string } }
  ```
- [ ] Implement sanitizer functions that construct these types from allow-listed fields only.
