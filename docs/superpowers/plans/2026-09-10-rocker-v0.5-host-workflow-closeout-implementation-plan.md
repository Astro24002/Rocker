# Rocker v0.5-A Host Workflow Closeout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the first v0.5 Hosts increment with safe duplicate/favorite/delete operations, exact group filtering, History-derived Recent Hosts, and reliable Host save errors.

**Architecture:** Keep Host mutations in the main-process `HostStore` and route them through the existing serialized mutation queue. Extend the typed preload bridge, then let `App` own canonical Host state while `HostList` owns selection, contextual action presentation, and transient action errors. Trust management remains outside this plan.

**Tech Stack:** Electron main process, React 19, TypeScript, lucide-react, Vitest, Testing Library, existing JSON stores and context-isolated IPC.

**Spec:** `docs/superpowers/specs/2026-09-10-rocker-v0.5-host-workflow-closeout-design.md`

## Global Constraints

- Keep the two-column desktop shell and compact Host card contract unchanged.
- A default card shows only platform mark, Host label, and `SSH · username`.
- Single click selects; double click connects; card hover exposes only Edit.
- Duplicate must remove credentials, private-key path/auth mode, Snippet association, and favorite state.
- Delete clears protected password/passphrase storage but does not close existing Terminal Sessions.
- Recent Hosts are derived from existing History; do not add a second recent-host store.
- All main-process mutations use the existing serialized mutation queue.
- Renderer code consumes typed IPC only and never imports HostStore or credential storage.
- Do not add Host Key Trust UI, tags, environment policy, connection test, charset/theme consumption, or Snippet execution in this increment.
- Preserve local-first storage, owner boundaries for existing runtime resources, and disabled-storage behavior.
- Write each behavior test before its implementation and run the focused test to observe the expected failure.
