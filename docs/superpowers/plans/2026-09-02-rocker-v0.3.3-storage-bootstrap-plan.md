# Rocker v0.3.3 Storage and Bootstrap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make Rocker local persistence crash-safe and prevent a failed Electron bootstrap from overwriting valid user data, then publish v0.3.3 after local verification.

**Architecture:** The Electron main process remains the sole owner of app-data files. A queued atomic `JsonStore` supplies backup, quarantine, schema normalization, and safe load outcomes to each adapter; typed bootstrap IPC aggregates those outcomes per renderer owner; the React renderer derives capabilities and only opens persistence gates for a valid workspace load.

**Tech Stack:** Electron main/preload IPC, TypeScript, React, Vitest, Node `fs/promises`, Electron `safeStorage`.

**Spec:** `docs/superpowers/specs/2026-08-31-rocker-v0.3.2-reliability-closure-design.md`

## Global Constraints

- Native Windows/macOS install and launch testing is deferred beyond v0.3.3 and is not a release gate.
- One Electron main process owns all app-data files; no cross-process file locking is added.
- Settings, History, and Workspace may default safely; Hosts, Credentials, and Host Keys fail closed without valid primary or backup data.
- Never overwrite a valid backup with invalid primary data.
- Never expose credentials, Host Key values, absolute paths, or raw filesystem errors to Renderer bootstrap.
- A blocked or rejected Workspace load keeps the workspace save gate closed.
- Do not add destructive reset or “clear all data” actions.
- Preserve the existing SSH/session/forwarding ownership model and existing UI layout.
