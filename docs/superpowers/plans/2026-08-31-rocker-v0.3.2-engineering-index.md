# Rocker v0.3.2 Engineering Plan Index

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Execute the approved v0.3.2 reliability closure as four sequential, independently reviewable engineering plans.

**Architecture:** Preserve the existing Electron main/renderer boundary. Establish runtime ownership first, then harden Connection/Session behavior, add resilient persistence and bootstrap, and finish with diagnostics plus release verification.

**Tech Stack:** Electron 43, TypeScript 7, React 19, ssh2, xterm.js, Vitest 4, GitHub Actions.

**Spec:** [Rocker v0.3.2 Reliability Closure Design](../specs/2026-08-31-rocker-v0.3.2-reliability-closure-design.md)

## Global Constraints

- Windows and macOS desktop only; do not add mobile behavior.
- This is a bug-fix release. Do not add v0.4 terminal productivity or v0.6 forwarding product scope.
- Do not reintroduce React-managed terminal output.
- Do not weaken Host Key confirmation or connection reuse identity matching.
- Only `network`, `timeout`, and `dns` may auto-retry.
- Never record credentials, key material or paths, agent endpoints, commands, terminal content, hostnames, usernames, or raw fingerprints.
- Do not add a global reliability supervisor or cross-process file locking.
- Do not tag, push, or publish v0.3.2 without a separate product-owner command.
- Every behavioral task begins with a focused failing test and ends with focused tests plus `npm run typecheck`.
- Execute the plans in order. Do not run overlapping plans concurrently in one shared worktree.

## Locked Cross-Plan Interfaces

Plan executors must use these names and shapes unless a compile-time conflict is
found. Any necessary change must update this index and every downstream plan in
the same documentation commit before implementation continues.

```ts

export interface RuntimeOwner {

// electron/ssh/connection-manager.ts
export type ConnectionFailureReason =
  | "network" | "timeout" | "dns" | "authentication"
  | "host-key-changed" | "host-key-rejected"

  kind: "terminal"

// electron/storage/storage-result.ts
export type StorageKind =
  | "settings" | "history" | "workspace"
  | "hosts" | "credentials" | "hostKeys"

export type StorageFailureReason =
  | "corrupt" | "permission" | "unavailable" | "recovery-failed"

export interface StorageIssue {
  store: StorageKind
  reason: StorageFailureReason
  message: string
}

export type LoadResult<T> =
  | { status: "ok"; value: T }
  | { status: "recovered"; value: T; source: "backup" }
  | { status: "defaulted"; value: T; reason: "missing" | "corrupt" }
  | { status: "blocked"; issue: StorageIssue }

export type StorageHealth =
  | { store: StorageKind; status: "ok" }
  | { store: StorageKind; status: "recovered"; source: "backup" }
  | { store: StorageKind; status: "defaulted"; reason: "missing" | "corrupt" }
  | { store: StorageKind; status: "blocked"; reason: StorageFailureReason; message: string }

// electron/ssh/types.ts
export interface RemoteExecOptions {
  timeoutMs: number
  maxOutputBytes: number
  signal?: AbortSignal
}
```

Owner-scoped managers provide both methods:

```ts
releaseOwner(owner: RuntimeOwner): Promise<void>
releaseWebContents(webContentsId: number): Promise<void>
```

`releaseOwner` is used for renderer reload/process-gone. `releaseWebContents` is
reserved for native Window close and application shutdown.

suites. Plan 4 owns the final full release matrix and soak.

## Cross-Plan Acceptance

- [ ] Cancelled connection acquisition has no pending waiter, lease, timer, or late state transition.
- [ ] A PTY callback invalidated by transport loss cannot reject while its Session continues recovery.
- [ ] Private-key and agent configuration failures never auto-retry.
- [ ] Keepalive uses `15_000` milliseconds and a maximum missed count of `3` in production.
- [ ] Store mutations are serialized and recover according to the approved policy table.
- [ ] Failed bootstrap cannot call Workspace save.
- [ ] Old renderer cleanup cannot release new-generation resources.
- [ ] The second Electron process exits before storage initialization and focuses the primary process.
- [ ] Monitoring commands are bounded to 8 seconds and 262,144 output bytes.
- [ ] Diagnostics cover window, storage, connection, PTY, and monitoring lifecycle without prohibited data.
- [ ] Full tests, typecheck, build, official-registry audit, and the 30-minute soak pass.
- [ ] Windows and macOS package smoke evidence is recorded before a v0.3.2 tag is authorized.
