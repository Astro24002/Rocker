# Rocker v0.4 Terminal Productivity Implementation Plan

> **For the implementation agent:** use `superpowers:executing-plans` and complete
> each task in order. Keep task commits separate so every boundary can be reviewed
> and reverted independently.

**Goal:** Make the existing SSH terminal comfortable for daily work by adding
per-session terminal search, a shared Command Palette/command registry, session
and terminal context-menu consistency, recent-session navigation, and live
terminal appearance preferences without changing SSH ownership or PTY semantics.

**Architecture:** Keep SSH connections, PTY channels, credentials, Host Key
verification, reconnect state, and storage ownership in the existing Electron
main process. Add renderer-owned command, search, palette, and recent-session
modules. xterm.js remains the terminal buffer and receives stream output
directly; React state must never accumulate terminal output.

**Tech stack:** Electron, React, TypeScript, xterm.js, `@xterm/addon-fit`,
`@xterm/addon-search`, Vitest, Testing Library, existing typed preload bridge.

**Design reference:**
`docs/superpowers/specs/2026-09-02-rocker-v0.4-terminal-productivity-design.md`

**Version policy:** Keep `package.json` at `0.3.3` during implementation. Do
not create a tag, release, or installer in this plan. The user controls the
first and second version numbers.

## Global Constraints

- Reserve only `Ctrl/Cmd+Shift+F` for Search and `Ctrl/Cmd+Shift+P` for the
  Command Palette.
- Never intercept `Ctrl+C`, `Ctrl+D`, `Ctrl+Z`, `Ctrl+L`, `Ctrl+A`, `Ctrl+E`,
  `Ctrl+F`, `Ctrl+K`, `Ctrl+U`, or `Ctrl+W` at the global command layer.
- Do not add `node-pty`, a native Local Terminal backend, tmux/screen support,
  AI commands, cloud sync, SFTP implementation, or arbitrary shortcut remapping.
- Preserve the existing same-window SSH reuse identity. "Duplicate in New
  Window" must continue to use an independent window and physical connection.
- Do not send terminal output, search state, or appearance settings through the
  main process except the existing typed Settings update bridge.
- Preserve the existing monitor HUD, sidebar order, split layout, Host Key checks,
  owner-window checks, and safe bridge failure categories.

## Task 1: Add bounded terminal appearance preferences

**Files:** `electron/storage/types.ts`, `electron/storage/settings-store.ts`,
`electron/storage/settings-store.test.ts`, `src/app/types.ts`,
`src/features/settings/SettingsView.tsx`, `src/features/settings/SettingsView.test.tsx`,
`src/features/terminal/terminal-controller.ts`,
`src/features/terminal/TerminalView.tsx`,
`src/features/terminal/TerminalWorkspace.tsx`, related App wiring and messages.

### 1.1 Write failing tests first

- Add normalization cases for `scrollback` values `1000`, `5000`, `10000`,
  `25000`, and `50000`; unknown, non-integer, and out-of-range values normalize
  to `10000`.
- Add normalization cases for `cursorStyle` (`block`, `underline`, `bar`),
  `cursorBlink`, and `terminalBell`; invalid values use `bar`, `true`, and
  `true` respectively.
- Assert these optional settings do not make a legacy settings snapshot unreadable
  and are not added to `requiredSettingsKeys`.
- Render SettingsView and assert the controls expose bounded options and emit one
  typed update per user change.
- Add TerminalController tests proving `applyPreferences` changes xterm options in
  place and does not reconnect, resize PTY generation, or dispose the controller.
- Add a multi-controller test proving one debounced preference update reaches every
  live controller.

Run the focused tests and confirm they fail before implementation:

```bash
npm test -- electron/storage/settings-store.test.ts src/features/settings/SettingsView.test.tsx src/features/terminal/terminal-controller.test.ts
```

### 1.2 Implement the storage and runtime contract

- Extend `AppSettings` with `scrollback: 1000 | 5000 | 10000 | 25000 | 50000`,
  `cursorStyle: "block" | "underline" | "bar"`, `cursorBlink: boolean`, and
  `terminalBell: boolean`.
- Add approved defaults to `defaultSettings` and normalize at the existing
  boundary. Read old snapshots safely and materialize defaults in normalized data.
- Extend `TerminalPreferences` with the same values and change
  `TerminalController.applyPreferences` to accept one preferences object.
  Mutate xterm options for font, size, scrollback, cursor style/blink, and
  `bellStyle` (`sound` or `none`) without creating a new xterm instance.
- Load preferences once when creating/restoring a Session. The controller remains
  the owner of xterm buffer state.
- Add SettingsView controls using native select/toggle controls. Keep the theme
  fixed to Rocker Dark; do not add a theme editor.
- Debounce persistence by 300 ms. Apply every update immediately to live
  controllers; persistence failure leaves the runtime value in memory and uses
  the existing unavailable-persistence state rather than claiming it was saved.
- Keep non-terminal settings behavior unchanged and preserve sidebar-width guards.

### 2.2 Implement the search controller and overlay

- Install the dependency at the repository's compatible version and keep it
  renderer-only.
- Define `TerminalSearchOptions`, `TerminalSearchState`, and a
  `TerminalSearchAdapter` around SearchAddon's `findNext`, `findPrevious`,
  `clearDecorations`, and result-change event. Hide xterm API details behind it.

  move React output into state.

## Final Acceptance Checklist

- Search is per Session, responsive over 10,000 generated scrollback lines, and
  never changes PTY, SSH, or terminal-input state.
- Only `Ctrl/Cmd+Shift+F` and `Ctrl/Cmd+Shift+P` are globally intercepted.
- All listed Linux shell combinations reach xterm unchanged.
- Palette, terminal menu, session menu, and visible buttons share one command
  implementation and identical enabled states.
- Reconnect, rename, duplicate, duplicate-in-new-window, split, and close keep
  existing owner-window and SSH reuse contracts.
- Recent Sessions are window-local and absent from persisted snapshots.
- Font, size, scrollback, cursor, blink, bell, and fixed theme settings apply to
  live terminals without reconnecting or clearing buffers.
- Blocked Settings storage permits temporary appearance changes and never claims
  persistence.
- Existing monitor HUD, Host Key verification, reconnect state machine, and
  packaging scope remain intact.
- `npm test`, `npm run typecheck`, `npm run build`, and production audit
  pass; no tag or release is created by implementation.
