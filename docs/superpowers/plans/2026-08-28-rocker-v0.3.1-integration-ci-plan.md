# Real SSH Integration Tests and CI Quality Gates Implementation Plan
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace fake-only transport confidence with deterministic in-process SSH integration tests and make every release build enforce the same quality gates.

**Architecture:** Run an `ssh2.Server` inside the Vitest node/Electron project. Tests exercise the public `SshConnectionManager` and `TerminalSessionManager` contracts with a generated test host key, while keeping the production resolver and host-key store boundaries injectable. Renderer tests remain in the existing jsdom project.

**Tech Stack:** `ssh2`, Node `net`/`crypto`, TypeScript, Vitest, GitHub Actions, npm audit.

**Spec:** Cover first host-key trust, password auth, PTY, UTF-8, input, resize, multiple-session reuse, transport loss/recovery, auth failure without retry, host-key change rejection, and session close without recovery.

## Global Constraints

- The fixture binds to `127.0.0.1` on an ephemeral port and closes every server/socket in `afterEach`.
- Generate or load only test keys; never use a developer's `~/.ssh` files.
- Tests must not require a network connection, Electron GUI, or platform-specific shell.
- Use the existing non-extending node project for `electron/**/*.test.ts`; do not restore unsupported Vitest 3 `environmentMatchGlobs` configuration.
- CI must fail explicitly when the npm audit endpoint is unavailable; an unavailable audit service is not a pass.

## Task 2: Exercise the connection/session contracts end to end

**Files:** `electron/ssh/terminal-integration.test.ts` (new), and only direct type/test-fixture helpers needed by it.

- [ ] Add a failing test that the first connection invokes host-key trust, stores the accepted key, and a second session with the same host/credential/key reuses the connection.
- [ ] Add a failing test that opens two PTY sessions, sends input, receives UTF-8 output, and observes resize dimensions at the server.
- [ ] Add a failing test that drops the transport, observes `reconnecting`, reconnects after the server is available, advances the channel generation, and emits `reconnected`.
- [ ] Add a failing test that rejects bad credentials with `authentication` and no retry timer.
- [ ] Add a failing test that presents a changed host key and receives `host-key-changed` without replacing the stored key.
- [ ] Add a failing test that closes the only terminal session and confirms no recovery event is emitted afterward.
- [ ] Keep assertions on typed state/events and connection counts; never assert against private manager fields.
