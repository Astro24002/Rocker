# Terminal Reliability and Failure UX Implementation Plan
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the `Connection -> Session -> Terminal` path stable under high output, resize, reconnect, restore, and shared-connection teardown, with clear non-blocking failure UX.

**Architecture:** Keep SSH transport in `electron/ssh/connection-manager.ts`, PTY/session ownership in `electron/ssh/terminal-session-manager.ts`, and terminal bytes in xterm.js. React stores only session metadata and receives typed `TerminalSessionEvent` state packets.

**Tech Stack:** TypeScript, ssh2, xterm.js, React, Vitest, Testing Library.

**Spec:** The approved v0.3.1 design requires states `idle`, `connecting`, `connected`, `reconnecting`, `disconnected`, `error`, `closing`; stable failure categories; retry only for network failures; and preservation of the terminal buffer across non-blocking errors.

## Global Constraints

- Modify only the files listed in each task unless a type export requires its direct owner file.
- Do not add a second connection owner or a React output accumulator.
- Preserve channel-generation and output-acknowledgement guards.
- Host-key prompts remain explicit and security failures never auto-retry.

## Task 1: Lock the state and failure vocabulary

**Files:** `electron/ssh/types.ts`, `electron/ssh/connection-manager.ts`, `electron/ssh/terminal-session-manager.ts`, `electron/ssh/reconnect-policy.ts`, corresponding `*.test.ts` files.

- [ ] Add failing tests asserting every connection failure maps to exactly one of `network | timeout | dns | authentication | host-key-changed | host-key-rejected | configuration | cancelled` (terminal-only `channel-ended`, `local-port-in-use`, and `unknown` remain explicit non-connection reasons).
- [ ] Add failing tests asserting `network`, `timeout`, and `dns` schedule retry, while authentication, host-key, configuration, and cancellation emit a terminal error without a retry timer.
- [ ] Add failing tests for retry policy changes at runtime: disabling auto-reconnect cancels pending retries; continuous mode has no finite attempt cap; limited mode respects the configured maximum.
- [ ] Implement the smallest typed mapping/policy changes in the existing managers. Keep emitted `TerminalStateEvent` fields (`channelGeneration`, `reason`, `attempt`, `nextRetryAt`) stable.
- [ ] Run `npx vitest run electron/ssh/*test.ts` and the strict scoped TypeScript command before moving on.

## Task 2: Prove output and resize are independent of React renders

**Files:** `src/features/terminal/TerminalView.tsx`, `src/features/terminal/TerminalWorkspace.tsx`, `src/features/terminal/session-state.ts`, `src/features/terminal/*.test.tsx`, and only the terminal CSS file if measurement exposes a layout defect.

- [ ] Add a failing test that emits a burst of output packets and verifies xterm's `write` path receives bytes without appending output to workspace React state.
- [ ] Add a failing test for stale `channelGeneration`: stale output and stale resize acknowledgements are ignored.
- [ ] Add a failing test that a `ResizeObserver`/layout change calls `sessions.resize(sessionId, generation, cols, rows)` with stable dimensions, including split-pane activation and font-size changes.
- [ ] Implement refs/effects around the existing xterm instance and resize observer. Keep `TerminalOutputPacket.bytes` as the only output transport and acknowledge packets after writing.
- [ ] Verify with focused renderer tests, then `npm test -- --runInBand` only if supported by the installed Vitest version; otherwise use the repository's plain `npm test` command.

## Task 3: Make recovery and shared leases observable and safe

**Files:** `electron/ssh/terminal-session-manager.ts`, `electron/ssh/connection-manager.ts`, `electron/ssh/terminal-session-manager.test.ts`, `electron/ssh/connection-manager.test.ts`.

- [ ] Add failing tests for two sessions sharing one connection: closing session A releases only A's lease; session B continues receiving output; the connection closes only after the final consumer releases.
- [ ] Add failing tests for transport loss and recovery: the session emits `reconnecting`, preserves its terminal buffer, creates a new channel generation, and emits `connected` with `notice: "reconnected"`.
- [ ] Add failing tests for user cancellation: `cancelReconnect` prevents later retry attempts and emits `disconnected`/`cancelled` exactly once.
- [ ] Add failing tests for restore: restoring a workspace creates a new shell when the old transport is gone and emits `notice: "restored-new-shell"`; it never claims the remote shell process survived.
- [ ] Implement lifecycle fixes using the existing owner/lease APIs. Every event subscription and retry timer must be disposed by `close`, `releaseOwner`, and application shutdown.

## Task 4: Define deterministic renderer failure presentation

**Files:** `src/features/terminal/terminal-error.ts` (new pure mapper), `src/features/terminal/TerminalConnectionOverlay.tsx`, `src/features/terminal/TerminalConnectionOverlay.test.tsx`, `src/i18n/en.ts`, `src/i18n/zh-CN.ts`.

- [ ] Add failing mapper tests for each failure category. Network/timeout/DNS expose retry and cancel; authentication/configuration expose retry and close/edit-host guidance; host-key failures expose a security-specific message and no silent retry.
- [ ] Add failing component tests for `connecting`, `reconnecting`, `disconnected`, and `error`, including accessible button names and a non-blocking `role="status"` overlay.
- [ ] Implement the pure presentation mapper and update the existing overlay without changing its compact HUD layout. The terminal content remains visible behind the overlay.
- [ ] Add English and Simplified Chinese strings for status labels, failure details, retry/cancel/close actions, and “terminal buffer preserved” copy.

## Task 5: Wire actions through typed IPC and verify the app workflow

**Files:** `src/app/App.tsx`, `src/app/App.test.tsx`, `electron/ipc/bridge-contract.ts`, `electron/preload.ts`, `electron/ipc/register.ts`, and their focused tests only if a new handler is needed.

- [ ] Add failing app tests that click Retry, Cancel reconnect, and Close and assert the corresponding `rocker.sessions` bridge methods are called once with the active session id.
- [ ] Add failing tests that renderer state clears retry metadata after a terminal `connected` or `cancelled` event and retains the active terminal component.
- [ ] Implement the minimum typed bridge wiring. Do not add a second ad-hoc event channel; use `TerminalSessionEvent`.
- [ ] Run focused App/overlay tests, then `npm test`, `npm run typecheck`, and `npm run build`.

## Acceptance Checklist

- [ ] High-frequency output does not cause React state growth or visible terminal stalls in the burst test.
- [ ] Resize reaches the remote PTY with the current channel generation.
- [ ] Retry behavior follows the category policy and user cancellation is authoritative.
- [ ] Shared connection leases survive individual session closure.
- [ ] Error UX is accessible, localized, non-blocking for network failures, and preserves the terminal buffer.
