# Connection and Session Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make connection acquisition, Session cancellation, PTY recovery, keepalive, and monitoring commands deterministic under failure.

**Architecture:** Keep transports and leases in `SshConnectionManager`, attempts and PTYs in `TerminalSessionManager`, and terminal bytes in xterm.js. Use AbortController only inside Electron main, generation-check every asynchronous callback, and expose finite typed failures to the renderer.

**Tech Stack:** TypeScript 7, ssh2, xterm.js, Vitest 4, in-process `ssh2.Server` fixture.

**Spec:** [Rocker v0.3.2 Reliability Closure Design](../specs/2026-08-31-rocker-v0.3.2-reliability-closure-design.md)

## Global Constraints

- Plan 1 must be complete; use `RuntimeOwner` everywhere.
- Do not serialize AbortSignal through IPC.
- Do not close a shared Connection while another lease or pending acquire remains.
- Only `network`, `timeout`, and `dns` may auto-retry.
- Keep production SSH keepalive at exactly 15,000 milliseconds and 3 missed responses.
- Preserve xterm.js buffers across Cancel, Disconnect, and Retry.
- Never put terminal bytes in React state or diagnostics.

- [ ] **Step 3: Implement provisional leases and abort-aware waiters**

Add these internal contracts:

```ts
export type ConnectionFailureReason =
  | "network" | "timeout" | "dns" | "authentication"
  | "host-key-changed" | "host-key-rejected"
  | "configuration" | "cancelled"

export class ConnectionFailureError extends Error {
  public constructor(
    message: string,
    public readonly reason: ConnectionFailureReason,
    options?: ErrorOptions
  ) { super(message, options) }
}

interface ConnectionReadyWaiter {
  leaseId: string
  resolve(): void
  reject(error: Error): void
  disposeAbort(): void
}

interface KeepalivePolicy {
  intervalMs: number
  countMax: number
}
```

Add the first lease before awaiting ready so every pending acquire is visible in
the record. `waitForReady(record, lease, signal)` attaches one abort listener;
abort removes that waiter and releases that lease. When no leases remain,
`close(record)` invokes `cancelConnect`, cancels retry timers, ends the client,
and rejects remaining waiters once.

Inject `readPrivateKey?: typeof readFile` and
`keepalivePolicy?: KeepalivePolicy` through `SshConnectionManagerOptions` for
deterministic tests. Production defaults remain `15_000/3`. Wrap key and agent
setup failures in a safe configuration error that does not contain a path.

- [ ] **Step 3: Implement transport-aware shell settlement**

Expose `transportGenerationForConnection(connectionId): number` from the
Connection manager. Capture it before `client.shell()`. In the callback and
after channel creation, validate:

```ts
const valid = this.isCurrentAttempt(record, attempt.id) &&
  !attempt.controller.signal.aborted &&
  record.connectionId === connectionId &&
  this.options.connections.transportGenerationForConnection(connectionId) === transportGeneration &&
  record.recoveryDesired
```

If invalid, end a returned channel and reject with
`TerminalStartInvalidatedError` regardless of the callback's raw error.
`open()` and recovered-start handling treat only this internal error as a reason
to continue waiting. A current-generation PTY error remains a terminal error.

Attach an abort listener to the shell Promise. Abort rejects immediately with
`cancelled`; the eventual callback still applies the generation check and ends
any returned stale channel.

```ts
export interface RemoteExecOptions {
  timeoutMs: number
  maxOutputBytes: number
  signal?: AbortSignal
}

export class RemoteOperationError extends Error {
  public constructor(
    message: string,
    public readonly reason: "timeout" | "cancelled" | "output-limit" | "channel-error"
  ) { super(message) }

```

Update both command executor interfaces to accept `options?:
RemoteExecOptions`. In `execOnConnection`, validate bounds, install one

command. `LinuxMetricsSampler` explicitly overrides those defaults with the
