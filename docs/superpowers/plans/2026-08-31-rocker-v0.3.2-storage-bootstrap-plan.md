# Storage and Bootstrap Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serialize local document mutations, recover from corrupt files without erasing security data, and prevent failed renderer bootstrap from overwriting persisted state.

**Architecture:** Put atomic file integrity and path-scoped mutation queues in `JsonStore`, keep schema and fallback policy in each adapter, aggregate only safe load status through typed bootstrap IPC, and make renderer save gates explicit. The application remains usable in a bounded degraded mode.

**Tech Stack:** Node `fs/promises`, Electron safeStorage, TypeScript 7, React 19, Vitest 4, Testing Library.

**Spec:** [Rocker v0.3.2 Reliability Closure Design](../specs/2026-08-31-rocker-v0.3.2-reliability-closure-design.md)

## Global Constraints

- Plan 1 must be complete so IPC requests have a current `RuntimeOwner`.
- One Electron main process owns all app-data files.
- Settings, History, and Workspace may safely default; Hosts, Credentials, and Host Keys fail closed without a valid backup.
- Never overwrite a valid backup with an invalid primary.
- Never expose credential values, Host Key values, absolute file paths, or raw filesystem errors to renderer bootstrap.
- A blocked or rejected Workspace load must keep the Workspace save gate closed.
- Do not add a destructive reset action.

- [ ] **Step 3: Implement the exact storage contracts**

Create:

```ts
export type StorageKind =
  | "settings" | "history" | "workspace"
  | "hosts" | "credentials" | "hostKeys"

export type StorageFailureReason =
  | "corrupt" | "permission" | "unavailable" | "recovery-failed"

export interface StorageIssue {
  store: StorageKind
  reason: StorageFailureReason
  message: string
}

export type LoadResult<T> =
  | { status: "ok"; value: T }
  | { status: "recovered"; value: T; source: "backup" }
  | { status: "defaulted"; value: T; reason: "missing" | "corrupt" }
  | { status: "blocked"; issue: StorageIssue }

export type StorageHealth =
  | { store: StorageKind; status: "ok" }
  | { store: StorageKind; status: "recovered"; source: "backup" }
  | { store: StorageKind; status: "defaulted"; reason: "missing" | "corrupt" }
  | { store: StorageKind; status: "blocked"; reason: StorageFailureReason; message: string }

export class StorageBlockedError extends Error {
  public constructor(public readonly issue: StorageIssue) {
    super(issue.message)
  }
}
```

Implement the generic API:

```ts
interface JsonStoreOptions<T> {
  filePath: string
  store: StorageKind
  defaultValue: T
  recovery: "default" | "blocked"
  normalize(value: unknown): T | undefined
  sensitive?: boolean
  clock?: () => Date
  nextOperationId?: () => string
}

load(options?: { consumeHealth?: boolean }): Promise<LoadResult<T>>
read(): Promise<T>
update(mutator: (current: T) => T): Promise<T>
write(value: T): Promise<void>
```

Use a static Map keyed by resolved file path to serialize the complete load or
mutation transaction across multiple store instances in the same process. Use
same-directory unique temporary files. Validate serialized data before writing,
copy a valid primary through a unique backup temp to `.bak`, then promote the
new primary. On first write, create `.bak` from the validated new primary.

When backup recovery succeeds, atomically restore the backup value to the
primary and latch the `recovered` health result in the store instance. Likewise,
latch `defaulted/corrupt` and `blocked` results. `read()` never consumes this
health. `load({ consumeHealth: true })` returns the current value with the
latched result and then clears a non-blocked notice; blocked health remains until
a valid load succeeds. This lets main restore a Window before renderer bootstrap
without losing the recovery notice. Ordinary `defaulted/missing` first-run
state is not latched as a warning.

If quarantine rename fails, return `blocked`; do not continue with a write.
Classify `EACCES/EPERM` as permission and other I/O as unavailable, using fixed
safe messages without a path.

For recovery policy `blocked`, treat a missing primary as first-run default only
when no matching quarantine file exists. A matching quarantine keeps the store
blocked across restarts until a valid primary or backup appears.

- [ ] **Step 3: Implement safe bootstrap aggregation**

Add bridge methods:

```ts
bootstrap: {
  load(): Promise<AppBootstrapSnapshot>
  retry(resources: BootstrapResourceName[]): Promise<Partial<AppBootstrapSnapshot>>
}
```

The IPC handler derives `RuntimeOwner` from `event.sender`, loads resources
independently with `Promise.allSettled`, and converts unexpected rejections to
safe blocked health. Workspace selection stays inside
`WorkspaceWindowManager.loadWorkspaceWithStatus(owner)` so the renderer never
receives another Window's snapshot.

Use this exact owner-scoped signature:

```ts
loadWorkspaceWithStatus(
  owner: RuntimeOwner,
  options?: { consumeHealth?: boolean }
): Promise<BootstrapResource<StoredWorkspaceWindow | undefined>>
```

Initial bootstrap and Retry request store status with `consumeHealth: true` only
after values needed for the response have been read. Earlier main-process
settings/workspace reads use the default non-consuming form.

Credential and Host Key resources return health only. Do not add values to
their `BootstrapResource` objects.

In `startApplication`, load Settings and Workspace status without consuming
their notable health. If Settings is blocked by permission/I/O, use
`defaultSettings` only as an in-memory retry-policy input and do not write it.
If Workspace is blocked, create one ephemeral Window without restoring or
persisting an empty document; renderer bootstrap receives blocked health and
keeps its save gate closed.
