# Diagnostics and Release Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete safe lifecycle diagnostics, prove resource cleanup under repeated real SSH failures, and make the v0.3.2 release gate reproducible.

**Architecture:** Extend the existing allow-listed diagnostic schema rather than logging raw objects, expose safe internal resource counts for tests, run a deterministic in-process SSH soak outside ordinary per-commit CI, and gate tagged releases on soak plus existing build jobs. Keep Windows/macOS installer interaction as recorded release-candidate smoke evidence.

**Tech Stack:** Electron 43, TypeScript 7, ssh2, Vitest 4, Node child processes, GitHub Actions, electron-builder.

**Spec:** [Rocker v0.3.2 Reliability Closure Design](../specs/2026-08-31-rocker-v0.3.2-reliability-closure-design.md)

## Global Constraints

- Plans 1-3 must be complete.
- Diagnostic recording and export remain local and fail-open.
- Diagnostic inputs are allow-listed; never serialize raw Error or request objects.
- The 30-minute soak is a tagged-release gate, not an ordinary push/PR gate.
- Eight-hour continuous use remains a whole-product dogfooding objective, not this patch's CI duration.
- Keep release assets limited to the existing six x64/arm64 Windows/macOS files.
- Prepare package version `0.3.2`, but do not create a tag, push, or publish without a separate command.

- [ ] **Step 2: Run short soak and confirm RED**

- [ ] **Step 3: Implement the cycle and cross-platform runner**

`scripts/run-soak.mjs` parses `--duration-ms`, defaults to `1_800_000`, rejects
values below 1,000, and spawns the local Vitest executable with environment:

```js
{
  ...process.env,
  ROCKER_SOAK: "1",
  ROCKER_SOAK_DURATION_MS: String(durationMs)
}
```

Implement `runTerminalSoak` in `electron/ssh/terminal-soak.ts`; keep the Vitest
file responsible only for environment parsing and assertions. The test is
skipped during ordinary `npm test` unless `ROCKER_SOAK === "1"`.
Each cycle opens two Sessions, streams bounded UTF-8 output, resizes, samples
monitoring, retains one local forward, drops/reconnects transport, closes one
Session, then releases the Window owner. After each cycle, manager and fixture
counts must equal baseline. The soak subscribes to output events and calls
`sessions.ackOutput(sessionId, channelGeneration, sequence)` for every accepted
packet so output backpressure is exercised without stalling on an absent
renderer. Baseline cleanup waits up to 5 seconds for asynchronous channel and
socket close events, then fails with the count-only snapshot.

Collect RSS once per cycle. Ignore the first five minutes. Compare the final
five-minute median to the minutes-five-through-ten median and fail above 1.25.
For short developer runs under ten minutes, report memory but gate only exact
resource baseline and uncaught failures.

Print one final line prefixed `ROCKER_SOAK_SUMMARY=` followed by JSON containing
duration, iterations, failures, reconnects, maximum count-only resources, and
RSS medians. Never include terminal output or SSH configuration.
