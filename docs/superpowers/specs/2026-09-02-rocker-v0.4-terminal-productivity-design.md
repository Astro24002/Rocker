# Rocker v0.4 Terminal Productivity Design

Date: 2026-09-02
Status: Approved for implementation planning
Scope: Windows and macOS desktop application
Roadmap: [Rocker Product Roadmap](./2026-08-28-rocker-product-roadmap-v0.4-v0.9.md)

## 1. Product Intent

Rocker v0.4 makes the existing reliable SSH terminal comfortable for daily
work. It adds fast local navigation and terminal actions without changing the
SSH protocol, PTY ownership, connection reuse rules, Host Key verification,
reconnect state machine, or storage safety guarantees established in v0.3.

The product promise for this version is:

> Find terminal content and execute a known terminal action quickly, while
> keeping the remote shell's keyboard behavior intact.

The version remains a Windows and macOS desktop release. Mobile, cloud sync,
AI commands, tmux integration, terminal recording, shell restoration, and a
real Local Terminal remain outside this design.

## 2. User Experience

### 2.1 Terminal Search

Search is a compact floating overlay in the upper-right area of the active
terminal. It does not replace the terminal, change the current PTY, or move
the remote shell cursor.

Default entry point:

```text
Windows: Ctrl+Shift+F
macOS:   Command+Shift+F
```

Behavior:

- Open with the platform shortcut or the Search command.
- Search as the user types through xterm.js SearchAddon.
- Show current match position and total match count when available.
- `Enter` selects the next match; `Shift+Enter` selects the previous match.
- `Escape` closes the overlay and returns focus to the terminal.
- Support case-sensitive, whole-word, and regular-expression modes.
- Keep search state per Session; switching Sessions never reuses another
  Session's query or match position.
- Preserve the terminal's current input and scrollback content after closing.
- Show an explicit no-results state without affecting terminal input.

The first release does not search across Sessions, hosts, persisted history,
or remote files. Search history is not persisted.

### 2.2 Command Palette

Command Palette is a centered, compact modal overlay opened with:

```text
Windows: Ctrl+Shift+P
macOS:   Command+Shift+P
```

It contains a fuzzy query field and grouped commands. Arrow keys move the
selection, `Enter` executes the selected command, and `Escape` closes the
palette. The palette closes after a successful action and focus returns to the
terminal or destination view.

The palette shows disabled commands when the current context cannot execute
them. Disabled commands are visible for discoverability but never invoke a
bridge method.

### 2.3 Command Registry

All command entry points consume one renderer-owned registry. Buttons, the
palette, the terminal context menu, session context menus, and the two global
shortcuts must not contain independent command implementations.

The registry shape is conceptually:

```ts
type TerminalCommand = {
  id: string
  label: string
  category: "terminal" | "session" | "navigation"
  shortcut?: string
  isEnabled: (context: CommandContext) => boolean
  execute: (context: CommandContext) => void | Promise<void>
}
```

Terminal commands:

- Search
- Copy
- Paste
- Select All
- Clear
- Focus Terminal
- Increase Font Size
- Decrease Font Size
- Reset Font Size

Session commands:

- Reconnect
- Rename Session
- Duplicate
- Duplicate in New Window
- Split Horizontally
- Close Session

Navigation commands:

- Hosts
- History
- Ports
- Settings
- SFTP
- Snippets
- Local Terminal

SFTP, Snippets, and Local Terminal remain explicit placeholder destinations
until their planned product versions. Their commands navigate to those
destinations and do not claim that the underlying feature is available.

### 2.4 Session Context Menu and Recent Sessions

The session context menu remains attached to the session row and contains:

```text
Reconnect
Rename
Duplicate
Duplicate in New Window
Split Horizontally
Close
```

`Duplicate` follows the existing same-window SSH reuse identity. `Duplicate in
New Window` always creates an independent window and physical SSH connection.
Rename changes only the display label. It never changes the Host profile,
connection reuse key, credentials, or Host Key identity.

The Sidebar session order and split layout stay stable. Session activation
updates an in-memory `lastFocusedAt` value. When Command Palette has an empty
query, it shows `Recent Sessions` sorted by that value. Recent ordering is
window-local and is not persisted across application restarts.

### 2.5 Clipboard and Terminal Context Menu

The terminal context menu exposes Copy, Paste, Select All, Search, Clear, and
Focus Terminal. Copy is enabled only when xterm has a selection; Paste remains
subject to the existing multiline-paste confirmation setting. Without a
selection, `Ctrl+C` remains terminal input and sends an interrupt to the
remote shell.

## 3. Keyboard Policy

Rocker intentionally reserves only two global keyboard combinations:

```text
Ctrl/Cmd+Shift+F  Search
Ctrl/Cmd+Shift+P  Command Palette
```

The following common shell combinations are never intercepted by the global
command layer:

```text
Ctrl+C  Ctrl+D  Ctrl+Z  Ctrl+L  Ctrl+A
Ctrl+E  Ctrl+F  Ctrl+K  Ctrl+U  Ctrl+W
```

Unrecognized key events are passed to xterm.js. v0.4 does not provide
arbitrary user shortcut remapping, script bindings, operating-system-level
global shortcuts, or per-command shortcut configuration. This keeps Linux
readline, tmux, and remote shell behavior predictable even when Rocker is
running on Windows or macOS.

## 4. Terminal Appearance Settings

Settings extends the existing terminal fields with a small, bounded set of
options:

| Setting | Values | Default | Persistence |
| --- | --- | --- | --- |
| Terminal Font | existing approved font names | existing value | SettingsStore |
| Font Size | 10-24 | existing value | SettingsStore |
| Scrollback Lines | 1,000 / 5,000 / 10,000 / 25,000 / 50,000 | 10,000 | SettingsStore |
| Cursor Style | block / underline / bar | bar | SettingsStore |
| Cursor Blink | on / off | on | SettingsStore |
| Terminal Bell | on / off | on | SettingsStore |
| Color Theme | Rocker Dark only | Rocker Dark | no custom persistence |

Settings are applied immediately to every xterm instance in the current
window. A 300 ms debounce coalesces updates before writing to SettingsStore.
Applying a setting never reconnects SSH, recreates a PTY, or clears a terminal
buffer. Newly created and restored Sessions use the latest settings snapshot.

If Settings storage is blocked, the user can still make temporary runtime
changes; the UI must identify that persistence is unavailable and must not
claim the change was saved.

Scrollback remains owned by xterm.js. It is never accumulated in React state,
written into Workspace snapshots, or sent to the main process as terminal
output.

## 5. Architecture and Data Flow

```text
Keyboard shortcut / button / context menu
                 |
                 v
       TerminalCommandRegistry
          |                |
          v                v
  xterm/SearchAddon     typed bridge
                          |
                          v
                 existing main-process owner
```

Renderer responsibilities:

- Register command definitions and derive enabled state from active Session
  context.
- Own palette, search overlay, recent-session ordering, and UI focus.
- Keep search state and xterm instances Session-local.
- Apply visual settings to live TerminalController/xterm instances.

Main-process responsibilities remain unchanged:

- Own SSH connections, PTY channels, credentials, Host Keys, and app-data
  files.
- Validate and execute existing Session, Workspace, Settings, and navigation
  bridge requests.
- Continue enforcing owner-window and channel-generation checks.
- Continue returning bounded failure categories instead of raw errors.

The only new dependency is the xterm.js SearchAddon package. No `node-pty`,
native Local Terminal backend, or new SSH transport is introduced.

## 6. State and Error Rules

Command context must distinguish at least:

- no active Session;
- active and connected Session;
- active Session that is connecting or reconnecting;
- active Session that is disconnected or in terminal error;
- Session with a current text selection.

Expected availability:

| Context | Search | Copy | Paste | Clear | Reconnect | Session actions |
| --- | --- | --- | --- | --- | --- | --- |
| No active Session | disabled | disabled | disabled | disabled | disabled | navigation only |
| Connected | enabled | selection-dependent | enabled | enabled | disabled | enabled |
| Connecting/reconnecting | enabled if buffer exists | selection-dependent | disabled | enabled | disabled | rename/close enabled |
| Disconnected/error | enabled if buffer exists | selection-dependent | disabled | enabled | enabled | rename/duplicate/close enabled |

Search and local appearance errors are renderer-local and must not disconnect
the SSH Session. Bridge command failures use the existing safe failure reason
and compact notification surfaces. No raw exception, credential, host key,
terminal output, or filesystem path is displayed by the new UI.

## 7. Testing and Acceptance

Unit tests must cover:

- command registry categories and enabled-state derivation;
- exact platform shortcut matching and pass-through of shell combinations;
- fuzzy palette filtering, keyboard selection, disabled commands, and close;
- per-Session search state, next/previous behavior, match count, no-results,
  and option toggles;
- recent-session ordering and removal after close;
- settings normalization and debounced multi-session application;
- terminal context-menu clipboard guards.

Integration tests must cover:

- Search over at least 10,000 generated scrollback lines;
- Palette, context menu, and button invoking the same command implementation;
- Rename preserving Host identity and SSH reuse state;
- Duplicate and Duplicate in New Window preserving existing connection rules;
- appearance changes preserving PTY generation, connection identity, and
  terminal buffer;
- blocked Settings allowing temporary changes without a false saved state;
- placeholder navigation for SFTP, Snippets, and Local Terminal.

Release acceptance:

1. Search remains responsive with 10,000 lines of scrollback.
2. Search does not alter PTY state, SSH connection state, or remote shell
   cursor input.
3. Only `Ctrl/Cmd+Shift+F/P` are globally intercepted.
4. All common Linux shell combinations listed in Section 3 reach xterm.
5. Palette, context menu, and visible buttons produce identical command
   behavior and disabled states.
6. Font, cursor, bell, and scrollback changes do not reconnect or clear a
   Session.
7. Session rename, duplicate, split, close, and recent ordering preserve the
   existing owner and connection contracts.
8. `npm test`, `npm run typecheck`, and `npm run build` pass.

## 8. Explicit Non-Goals

- Real Local Terminal or `node-pty`.
- tmux/screen integration or remote process restoration.
- Terminal recording, output export, or cross-session search.
- AI-generated commands, command scripts, or custom command definitions.
- Arbitrary shortcut remapping or system-wide global shortcuts.
- Custom theme editor, theme marketplace, or per-host themes.
- SFTP implementation, Security Center, or the v0.6 Port Forwarding manager.
- Mobile clients, cloud sync, team libraries, and telemetry.
