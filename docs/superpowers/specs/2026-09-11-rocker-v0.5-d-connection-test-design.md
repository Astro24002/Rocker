# Rocker v0.5-D Connection Test Design

Date: 2026-09-11
Status: Implemented in the working tree; not a release record
Scope: Explicit saved-Host connectivity testing for the Windows and macOS desktop app

## Goal

Give a user an explicit, bounded way to verify a saved Host without opening a
terminal Session. The action belongs to the selected Host action strip and must
not change the existing terminal connection reuse graph.

## Interaction Contract

- A Host is still selected with one click and connected with a double click.
- `Test connection` is available only in the selected Host action strip.
- The action reports a safe success or failure state in the Hosts view. It does
  not add a History entry and does not expose raw SSH errors, credentials, key
  paths, or Host Key fingerprints to the renderer.
- A successful result includes only bounded connection latency. Failure is a
  stable category (`network`, `timeout`, `dns`, `authentication`, Host Key
  category, `configuration`, or `cancelled`) that the UI maps to generic copy.

## Transport Contract

```text
selected Host
    |
    v
Host resolver + protected credentials
    |
fresh ssh2.Client (no PTY, no lease, no manager record)
    |
Host Key inspection / existing confirmation / trust or replacement
    |
bounded ready probe
    |
close client and return safe result
```

- The probe always uses a fresh transport. It never acquires a terminal lease,
  registers a reusable connection, starts a PTY, runs a remote command, or
  changes an existing connection's retry state.
- Resolution goes through the existing connection resolver, so the selected
  Host's current credential protection and security context are honored.
- Host Key checks use the same inspection and prompt/trust/replace callbacks as
  normal SSH sessions. Rejecting an unknown or changed key fails the probe;
  approving it follows the existing persisted trust policy.
- The probe has one 30-second end-to-end budget, including protected Host
  resolution. The saved connection timeout can shorten the transport portion,
  but renderer input cannot extend the cap. Abort signals settle as
  `cancelled`.
- The temporary client is closed on success, failure, timeout, and cancellation.

## IPC Contract

```ts
hosts.testConnection(hostId: string): Promise<ConnectionTestResult>
```

The main process validates the Host ID, scopes the request to the current
renderer owner, and delegates to `SshConnectionManager.testConnection`. The
owner is checked before and after the asynchronous probe. The result is a
small discriminated object and contains no secret or raw diagnostic message.

## Preview Contract

The browser preview implements the same bridge method with a deterministic
reachable result so the Hosts workflow remains demonstrable and testable
without a native SSH transport.

## Acceptance

- A successful probe returns `reachable` with a non-negative latency and leaves
  `resourceSnapshot()` unchanged.
- A probe does not reuse an already-ready terminal connection and does not emit
  connection-manager lifecycle events.
- Timeouts, transport failures, resolver failures, and Host Key rejection are
  categorized without returning sensitive details.
- Every probe closes its temporary client and honors cancellation.
- IPC rejects malformed Host IDs and renderer-owner replacement.
- Hosts keeps click-to-select and double-click-to-connect semantics while
  exposing the selected Host's test action.
- Focused and full automated verification remains green. Native launch and the
  v1 soak remain deferred under the v0 policy.

## Deferred

Remote health commands, latency history, continuous monitoring, port probing,
and per-Host test scheduling are outside this increment.
