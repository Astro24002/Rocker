# Rocker v0.5-C Host Organization Design

Date: 2026-09-11
Status: Implemented in the working tree; not a release record
Scope: Windows and macOS desktop application, Host organization metadata

## Goal

Make a saved Host easier to find and safer to operate without changing the
approved compact card surface. Environment and tags are profile metadata, not
credentials and not a second persistence model.

## Data Contract

```ts
type HostEnvironment = "production" | "staging" | "development" | "personal"

interface HostProfile {
  environment?: HostEnvironment
  tags?: string[]
}
```

- Both fields are optional. Missing or unknown environments normalize to
  unset; legacy Host documents remain readable.
- Tags are trimmed, case-preserving, case-insensitively deduplicated, limited
  to 16 entries, and limited to 64 characters per entry. Empty tags are
  omitted. Host documents never contain secrets in these fields.
- Duplicate preserves environment and tags as safe display metadata while
  continuing to drop all authentication material, private-key paths, Snippet
  association, and favorite state.

## UI Contract

- The Host card remains platform mark, label, and `SSH · username` only.
- New/Edit Host exposes an optional Environment select and comma-separated
  Tags field with visible labels. Empty values are valid and omitted.
- Hosts search includes name, address, username, group, environment, and tags.
- Compact filter controls add Environment and Tag selectors beside the existing
  group and Recent filters. Exact normalized identity is used for all filters.
- A production Host uses a stronger delete confirmation that explicitly names
  the production environment and warns that protected credentials are removed.
  No confirmation is added to ordinary non-destructive selection.

## Security and Compatibility

- IPC validates bounded tags and the enumerated environment before HostStore
  mutation. HostStore normalizes again when loading and saving.
- Configuration export/import carries the non-secret metadata through the
  existing Host profile path; credential and Host Key boundaries are unchanged.
- Browser preview mirrors normalization and duplicate behavior so UI tests use
  the production-facing contract.

## Acceptance

- Legacy Host documents without the fields load unchanged.
- Invalid optional values cannot create a misleading saved environment/tag
  state.
- Search and selectors find Hosts by exact environment/tag identity while
  retaining existing group/recent behavior.
- Production deletion has an explicit risk message; cancel leaves the Host.
- No compact card adds address, port, tags, environment lights, or menus.
- Focused and full automated verification remains green; native launch and the
  v1 soak remain deferred under the v0 policy.

## Deferred

Connection testing, Session security summary, Host charset/theme runtime
application, managed Group CRUD, tag editing outside the Host profile, and
SFTP/Snippets remain outside this increment.
