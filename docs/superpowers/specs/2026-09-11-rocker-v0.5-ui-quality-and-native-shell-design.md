# Rocker v0.5.x UI Quality and Native Shell Design

Date: 2026-09-11
Status: Approved implementation sequence
Scope: Windows and macOS desktop application

## Purpose

The current Rocker UI has the correct product direction: a dark terminal-first
workspace, a compact Host card surface, a resizable Sidebar, Session-level
actions, and the `#0AA344` Rocker accent. The next work is quality closure, not
another feature surface.

This document turns the UI audit into a versioned implementation sequence for
the `v0.5.x` line. It preserves the existing Hosts/Trust product boundary and
orders the work by user impact:

```text
1. Focus, keyboard, and interaction semantics
2. English and Simplified Chinese completeness
3. Windows/macOS native window shell behavior
4. Workspace interaction resilience
5. Visual polish, motion preferences, and desktop-size resilience
```

`v0.5.0` remains the Hosts and Trust capability milestone. The versions below
are quality and integration increments; they do not create a second product
roadmap or expand the feature inventory.

## Product Contract

- The app remains a continuous two-column desktop workspace. Sidebar is the
  durable control surface and the right Workspace is the destination surface.
- An active SSH Session keeps the right Workspace dedicated to the terminal.
  No permanent monitor, toolbar, title strip, or Local Terminal surface is
  reintroduced.
- Hosts keeps the compact card contract: platform mark, Host label, and
  `SSH · username`. Single click selects; double click connects; hover exposes
  only Edit.
- Session operations remain in the Session context menu. The menu must be
  reachable by pointer and keyboard and must return focus to its origin.
- The `#0AA344` accent, semantic CSS tokens, Lucide icon family, and bounded
  card radius remain the visual baseline.
- Existing SSH connection reuse, Host Key verification, credential protection,
  workspace restore, port-forward ownership, and diagnostic sanitization are
  unchanged.

## Release Sequence

| Version | Focus | Required outcome | Explicit non-goals |
| --- | --- | --- | --- |
| `v0.5.1` | Accessibility and keyboard semantics | Every important control has a visible focus state, correct selected/expanded semantics, keyboard equivalents for Host connect and Session menus, and no pointer-only workflow | No new shortcuts beyond existing command policy; no visual redesign |
| `v0.5.2` | Localization and protection-form clarity | All visible and accessible product copy is available in English and Simplified Chinese; Vault and migration fields have visible labels, inline errors, and submit feedback | No change to credential encryption or migration format |
| `v0.5.3` | Native desktop shell | Windows and macOS render platform-appropriate window controls and drag regions while preserving the blank right-side chrome contract | No native launch/soak gate; no reintroduction of a global title bar |
| `v0.5.4` | Workspace interaction resilience | Sidebar collapse/resize, destination switching, Session focus return, and minimum-window layout remain stable without terminal state loss | No new Session metadata, runtime charset/theme behavior, or new destinations |
| `v0.5.5` | Visual polish and resilience | Reduced-motion support, token-only overlays, stable typography, responsive header behavior, and visual regression coverage are complete | No new navigation destinations or card information |

The product owner controls whether and when each patch tag is published. A
patch may be skipped only when its acceptance evidence is included in a later
patch without weakening the order above.

## 1. Accessibility and Keyboard Semantics

### Focus contract

- Use `--focus` for a consistent two-pixel `:focus-visible` ring with a
  two-pixel offset on buttons, inputs, selects, cards, menus, the resize
  separator, and custom command surfaces.
- No rule may remove the browser focus indicator unless the same rule supplies
  an equivalent ring or a high-contrast border plus ring.
- The focused Host card must remain visible when a drawer, menu, or recovery
  banner is open.

### State semantics

- Navigation exposes the active destination with `aria-current="page"`.
- Segmented language controls and Host filters expose their selected state with
  `aria-pressed` or an equivalent radio-group pattern.
- Session menu triggers expose `aria-expanded` and `aria-haspopup="menu"`;
  duplicate exposes its submenu state in the same way.
- Disabled actions remain native disabled controls and never invoke an IPC
  request.

### Keyboard equivalents

- A focused Host card remains selectable with Space. Enter invokes the existing
  Host connection path without changing the pointer rule that single click
  selects and double click connects.
- The Session context menu opens from the Context Menu key and Shift+F10 as
  well as the secondary pointer button. Escape closes it and restores focus to
  the originating Session row.
- The Sidebar resize separator keeps Arrow Left/Right support and exposes its
  current, minimum, and maximum width.
- No new global shortcut is reserved. Existing Linux shell combinations keep
  their current pass-through behavior.

## 2. Localization and Protection Forms

- Move all user-facing strings and accessible names in Hosts, History, Settings,
  Window Chrome, Sidebar, resize affordances, and recovery actions into the
  existing `en.ts` and `zh-CN.ts` catalogs.
- Protocol and platform values such as `SSH`, `Ubuntu`, `UTF-8`, and
  `GB18030` remain stable data labels; surrounding explanatory copy is
  translated.
- Vault password, confirmation, migration password, and encrypted-import
  password fields use visible labels, `autocomplete`, an explicit error/status
  region, and submit loading feedback. Placeholder text is supplementary only.
- Error copy identifies the field or operation that needs attention and never
  exposes password, private-key, Host Key, or raw storage details.
- Switching language updates the current Workspace without resetting Sessions,
  Host selection, drawer state, or terminal buffers.

## 3. Native Desktop Shell

The typed bridge already exposes `app.platform`; the renderer should use that
value to choose shell presentation without adding platform-specific business
logic to feature views.

- Windows keeps right-aligned minimize, maximize/restore, and close controls in
  the no-drag region.
- macOS uses a left-side traffic-light-compatible control zone or equivalent
  platform-native placement while preserving the draggable blank chrome. The
  close/minimize/maximize actions continue through the existing bridge.
- The Workspace remains the owner of the chrome. Sidebar branding does not move
  into the title strip, and no Session or Host title is rendered above the
  terminal.
- Maximize/restore state must be reflected by the control icon and accessible
  name; close retains the platform danger treatment.
- The native BrowserWindow background and the renderer canvas use the same
  semantic canvas token to prevent resize/startup flashes.

## 4. Workspace Interaction Resilience

This increment hardens the approved two-column shell without adding Session
metadata or changing the SSH output pipeline. It is concerned with preserving
visible state while the user changes workspace geometry or destination.

- Sidebar collapse, expansion, and pointer/keyboard resize preserve the active
  destination, selected Host, and active Session.
- Switching between Hosts, Trust, Settings, and the terminal does not create a
  duplicate Session or clear the terminal controller registry.
- Closing a Session menu restores focus to its originating Session row even
  after a resize or destination change; removed rows use the existing fallback
  focus path.
- The supported minimum desktop window keeps the Sidebar, resize handle, view
  header actions, and terminal surface reachable without overlap or horizontal
  scroll traps.
- Existing Host profile `charset` and `themeColor` metadata remain reserved and
  are not presented as effective terminal runtime settings in this release.

## 5. Visual Polish and Resilience

- Keep body text and persistent metadata at a readable desktop size; do not use
  9px text for essential state or action labels.
- Remove negative letter spacing from UI copy. Reserve uppercase labels for
  stable protocol/status metadata rather than repeating decorative eyebrows on
  every route.
- Replace hardcoded overlay, scrim, and status colors with semantic tokens so a
  future theme can change surfaces without editing component rules.
- Add `prefers-reduced-motion: reduce` coverage for transitions and the port
  refresh animation. Reduced motion must preserve the final state and status
  feedback.
- Allow Hosts and Settings header action groups to wrap or collapse at the
  supported minimum window size. No control may overlap or become unreachable.
- Keep the Host card compact and do not add address, port, favorite lights,
  three-dot menus, or connection buttons to the default card surface.

## Verification Matrix

### Automated

```text
npm run typecheck
npm test
npm run build
git diff --check
```

Focused tests must cover:

- focus rings and keyboard activation for Host cards, Session menus, filters,
  navigation, and resize separator;
- complete English/Simplified Chinese copy and no user-facing hardcoded strings
  in the audited routes;
- visible protection-field labels, validation, loading, success, and failure;
- Windows/macOS Window Chrome rendering from the typed platform value;
- Sidebar resize, destination switching, Session focus return, and
  minimum-size layout resilience;
- reduced-motion CSS behavior and minimum-size header layout;
- no change to existing SSH, Host Key, storage, forwarding, or restore tests.

### Manual desktop checks

Run when a native runner is available, without making native launch a v0
release gate:

1. Windows 10/11 at 1040x680, 1440x900, and maximized.
2. macOS at the equivalent minimum, normal, and maximized states.
3. Keyboard-only navigation through Hosts, Session menu, Settings, Vault, and
   the resize separator.
4. English/简体中文 switching while a Session is connected.
5. Sidebar collapse/resize and destination switching while a Session remains
   active; confirm the terminal controller and focus origin are preserved.
6. `prefers-reduced-motion` enabled while opening menus and refreshing ports.

## Non-Goals

- No SFTP implementation, Snippets execution, Mobile UI, Local Terminal,
  monitoring panel, AI, cloud synchronization, ProxyJump, SOCKS5, or remote
  forwarding.
- No redesign of the approved Hosts card information architecture.
- No new global keyboard shortcut family.
- No Session Security Summary, Host Charset / Terminal Theme Runtime, or
  1,000-host product-scale acceptance in the v0.5.x line.
- No v1 soak requirement. The long-running soak remains a v1 release gate.

## Exit Criteria

The `v0.5.x` UI quality sequence is complete when every patch row has its
focused tests and verification record, the full automated suite passes, the
Windows/macOS shell behavior has a recorded manual result or an explicit v0
native-test deferral, and no accepted product contract above is weakened.
