# Rocker v0.5-B Trust Design

Date: 2026-09-11
Status: Implemented in the working tree; not a release record
Scope: Windows and macOS desktop application, Host Key trust management

## Goal

Expose the Host Keys Rocker has already verified without turning Trust into a
telemetry dashboard or exposing credentials. The view lets a user inspect the
endpoint/fingerprint pair, review a bounded audit history, and remove one
entry when its expected fingerprint still matches.

## UI Contract

- Trust is a dedicated Sidebar destination after Hosts and uses the right
  Workspace surface.
- A trusted row shows the saved Host label when available, endpoint, and a
  `SHA256:` fingerprint. It never shows username, password, passphrase,
  private-key path, credential ID, or raw storage errors.
- Search matches Host label, endpoint, and fingerprint. Activity is newest
  first and capped at the latest 100 records in the renderer.
- Remove trust is an explicit action with a confirmation message containing
  the Host label and endpoint. There is no silent re-trust action; the next
  connection uses the existing native unknown-Host-Key confirmation flow.
- Blocked Host Key storage leaves the view navigable but disables removal and
  shows a generic availability state.

## Storage Model

`host-keys.json` keeps the existing `fingerprints` map and adds a `history`
array. Each history record contains only:

```ts
{
  at: string
  action: "trusted" | "replaced" | "removed"
  host: string
  port: number
  fingerprint: string
  previousFingerprint?: string
}
```

History is normalized on load, legacy documents without `history` become an
empty history, and only the newest 500 records are retained. Raw public-key
material and all credential values remain outside this document.

## IPC and Ownership

- `rocker:host-keys:list` returns `{ entries, history }` after checking the
  current renderer owner before and after both reads.
- `rocker:host-keys:remove` accepts `{ host, port, fingerprint }`, validates
  bounded input, rechecks the owner inside the serialized mutation queue, and
  uses compare-and-remove against the expected fingerprint.
- The preload bridge exposes only these typed operations; the browser preview
  mirrors the same stale-fingerprint behavior without widening production
  permissions.

## Acceptance

- Legacy Host Key files load without a migration prompt.
- Trust/replacement/removal operations record audit entries without secret
  material.
- A stale renderer generation cannot read or mutate the inventory.
- A changed stored fingerprint cannot be removed by an outdated request.
- English and Simplified Chinese Trust labels are available.
- Automated Trust, Host Key store, IPC, bridge, Sidebar, and command-registry
  tests pass; native launch checks remain deferred under the v0 policy.

## Deferred

Re-trust remains part of the existing SSH Host Key confirmation flow. Tags,
environment policy, connection testing, Host charset/theme runtime behavior,
native launch smoke, and the v1 long soak are outside this increment.
